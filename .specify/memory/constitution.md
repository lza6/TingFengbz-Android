# 项目宪法（Project Constitution）

> 听风插帧 TFGY999 —— Android 全局实时屏幕补帧工具。
> 本宪法约束本仓库一切开发决策；优先级高于惯例而低于安全底线。

## 核心价值

1. **屏幕隐私绝对底线**：MediaProjection 捕获的屏幕内容仅在设备内处理——不落盘、不上传、不进日志、不写入外部存储。任何改动不得破坏此承诺。
2. **真实闭环优先**：禁止占位实现、假数据、伪连接。宣称"完成"必须有可运行代码 + 可复现验证 + 文档同步。
3. **实时管线敬畏**：插帧是每帧实时循环（Choreographer + EGL）。热路径禁阻塞（IO/GC/锁）、禁每帧大分配；帧内存一律走 `DirectBufferPool`。
4. **用户可感知优先**：启动、权限、通知、停止——每个用户操作都要有明显、及时、可恢复的反馈。
5. **简洁克制**：不写投机代码、不做过度抽象；改必须改的，删该删的。

## 技术原则

### 架构
- 单模块 `:app`，包固定 `com.example.tfgy999`。
- 前台服务管生命周期（`AutoFrameBoostService`），`FrameInterpolator` 管渲染，`DirectBufferPool` 管内存，职责单一。
- 跨线程一律显式：渲染线程 = HandlerThread；上传线程 = HandlerThread；捕获回调 = Coroutine(IO)。

### 代码质量
- Kotlin 官方风格；`val` 优先、禁 `!!`、sealed 穷举；错误处理不静默吞噬。
- 函数 <50 行、文件 <800 行、嵌套 ≤4 层。
- JNI 命名 `Java_com_example_tfgy999_<Class>_<Method>`，改签名必须同步 CMake 源。
- Room DAO 参数化查询，禁字符串拼接 SQL。

### 性能
- 热路径零 `new byte[]`/`allocateDirect`（用池）；渲染/上传线程零 IO、零同步锁竞争。
- 启动时间受控：无 ContentProvider 主线程初始化（LeakCanary 教训）。

### 安全
- 权限最小化：只声明有代码使用的权限；受保护权限（CAPTURE_VIDEO_OUTPUT 等）不再引入。
- 签名口令 `keystore.properties` 永不入库；构建产物永不入库。

## 决策框架

技术选型与修复方案按序评估：
1. 是否违背安全底线（屏幕隐私/密钥）？
2. 是否破坏真实用户主链路？
3. 是否引入回归（启动/渲染/停止）？
4. 是否保持简单可维护（比现状更复杂则需要强理由）？
5. 是否有真实证据支撑（构建/测试/E2E/日志）而非理论？

## 版本与治理
- 本宪法随项目演进：新增重大教训或约束时修订并记录日期。
- 违反宪法的问题按 P0 处理。
