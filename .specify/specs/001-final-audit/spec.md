# 功能规格：001-终局闭环总审计（Final Audit & Hardening）

## 问题陈述（Problem Statement）

项目已具备：构建通过、单测通过、lint 通过、E2E（模拟器）验证通过、Release v1.0.0 发布、压枪移除。但此前工作以"修复已知点"为主，从未以**即将交付的真实产品**视角做全链路盲点审计。用户明确要求：找出"未知的未知"、补齐前后端（界面/服务/数据/权限/生命周期）衔接断点、消灭伪实现与半成品、更新文档与记忆、产出 HTML 报告+测验，并把项目整理为可复用 workflow/skill。

## 用户故事（User Stories）

### Story 1：核心补帧链路必须真实可用
As 用户
I want 打开 App→授权→启动服务→看到补帧生效→停止服务，全程稳定、有反馈
So that 我能安心长期使用。

**验收标准：**
- [ ] 启动/停止服务全流程无崩溃、无卡死（含快速启停、权限拒绝、中途断授权）
- [ ] 悬浮窗开关/历史记录跳转等每个按钮有真实行为与状态反馈
- [ ] 前台服务通知在 Android 13+ 可见（通知权限被正确请求）

### Story 2：无伪实现、无半成品
As 代码维护者
I want 代码里不存在占位/桩/假连接
So that 调用方不会点到"看起来能用其实没有"的功能。

**验收标准：**
- [ ] `MotionEstimator` 等占位实现要么真接入要么如实标注并从宣称中剔除
- [ ] README 宣称与实际实现一致（金字塔运动估算/NEON/光流等）
- [ ] 无死代码、无未注册的开关/按钮、无孤立广播接收器

### Story 3：生命周期与资源零泄漏
As 系统
I want 服务/渲染/上传/监听在停止与旋转时全部正确释放
So that 长时运行不积累内存、不累积监听器、不重复回调。

**验收标准：**
- [ ] `DisplayListener`/`Choreographer`/广播/Timer 全部有对称注销
- [ ] `DirectBufferPool` 无泄漏、无 double-release、重启不缩容
- [ ] EGL/GL 资源启停循环零增长

### Story 4：验收与文档闭环
As 交付团队
I want 需求追踪矩阵、workflow_status、测试验证记录、HTML 报告全部就位
So that 交接与回归不靠记忆、不翻旧账、可复验。

**验收标准：**
- [ ] `workflow_status.md` 实时反映任务节点状态
- [ ] 记忆区建立"验证记录"（范围/结果/时间），同范围测验不再盲跑
- [ ] HTML 报告含上下文、直觉、改动清单、底部测验
- [ ] README/CLAUDE.md/宪法与真实状态一致

## 非功能需求

- **性能**：修复不得引入热路径分配/锁/IO；启动不因审计修复而变慢。
- **安全**：屏幕内容零外部泄漏；签名口令不入库；权限最小化维持。
- **兼容性**：minSdk 24 / targetSdk 35 不动摇；不在低版本引入新崩溃。
- **可维护性**：新增逻辑遵循宪法；注释与命名表达意图。
- **可验证性**：每项修复有命令/测试/日志证据；无法实测项明确标注边界。

## 成功指标

- P0 全部修复并验证；P1 修复且无回归；P2 有明确处置。
- 核心链路（启动服务→补帧→停止）在模拟器可走通且进程稳定。
- 需求追踪矩阵每行能映射到真实代码/验证/文档。

## 范围外（Out of Scope）

- 真机/多机型矩阵测试（无设备资源；以模拟器 + 静态 + 单测为准并披露）。
- 付费外部 API 真调用（无预算、宪法禁止）。
- 后端/服务端基础设施（本项目为纯 Android 客户端；高并发 SaaS 技术栈不适用，专项说明于 plan）。
- 自动压枪/无障碍注入类功能（已按用户决定移除，不回归）。
