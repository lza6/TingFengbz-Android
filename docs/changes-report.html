1. 上下文（Context）

本仓库是一个 Android 全局屏幕补帧 App：用 MediaProjection 捕获屏幕，逐帧做插值处理，并提供悬浮窗帧率统计。此前已历经：自动压枪外挂移除 → v1.0.0 发布（Release 188.7MB→33.2MB、LeakCanary 启动 ANR 修复、DirectBufferPool 内存池接线、GL 资源泄漏修复、依赖瘦身）→ 本次终局闭环总审计。

本次审计的触发：用户要求以"即将交付的真实产品"视角做全链路盲点扫描，消灭伪实现/半成品/幽灵链路，补齐生命周期、权限、文档、记忆、报告，并沉淀可复用工作流。

2. 关键发现（直觉 / Findings）

🔴 P0-1 核心能力边界（平台约束，待产品决策）

插值结果被渲染到离屏 FBO/PBuffer，全仓库没有任何 SurfaceView/Presentation 把插值画面回投到真实屏幕。非 Root 下 Android 不允许把改写画面覆盖到其他应用的显示层——这是平台硬约束而非单纯漏写。当前刷新屏幕上看不到插值画面，只能看到统计数字。已如实写入 README「能力边界」，两个候选方向（悬浮窗回投 / 保持监控统计定位）留待用户拍板，不擅自大改核心渲染架构。
